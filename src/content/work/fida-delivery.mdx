## The operator dashboard

Every day at FIDA is run out of the operator panel — a Filament 5 admin on top of the Laravel 13 API, sharing the same auth pool and PostGIS locations as the customer and rider apps. I designed the operator UX end-to-end: what a dispatcher sees first at 7am, how a KYC review screen keeps a new rider from being blocked by a bad photograph, what pricing looks like as a heatmap of distance × hour, and what the ledger looks like when accounting closes the week.

The panel is organized as a small operating system for the business — **Operations** (Deliveries, Order Approvals, Rider SOS), **Users** (Customers, Riders, Providers, Team), **Catalog** (Items, Categories, Locations), **Finance** (Payments, Payouts, Refunds, Rider cash, Tariffs), **Trust & Safety** (KYC Verification, Blocked Identities, Disputes & Flags), and a **Reports** section (Deliveries, Revenue, Rider Performance, Ledger, Reconciliation, User Retention, App Traction). The live rider map runs on WebSockets over Laravel Reverb; auth adds TOTP on top of session; roles run through `spatie/laravel-permission`; every money field is stored and rendered as integer ETB cents so accounting never rounds.

Coverage on a delivery brand's home page is not decoration — it is the single question every visitor is asking: *do you serve me?* The map runs on **MapLibre GL** (not Mapbox or Google) because MapLibre has no SDK pricing, renders the same on Telegram in-app browser as it does on Chrome, and lets me ship a custom vector tile set keyed to FIDA's brand palette. ## The opening

Bishoftu is a city of two million people 47 km southeast of Addis Ababa, with no reliable on-demand delivery network. Local commerce runs on phone calls, motorbike couriers paid in cash, and a wall of *"can you bring this to my office?"* WhatsApp threads. FIDA's bet is that a well-designed set of surfaces — customer app, rider app, ops dashboard, marketing web — can replace that informal layer with something verifiable, dispatchable, and economically sustainable.

I co-founded FIDA and built the design and frontend end-to-end across all four surfaces. The product had to launch in a market with low smartphone uniformity, weak data connections, and zero brand recognition. Every surface had to be obviously trustworthy on the first screen, fast on 3G, and small enough to install over patchy Wi-Fi.

## Constraints that shaped the build

- **Four surfaces, one operator.** A unified design system was not a nice-to-have — it was the only way to ship customer + rider + admin + website before runway pressure hit.
- **Multilingual from day one.** Amharic and English need first-class treatment in every surface — including locale-aware numerals and date/time formatting via `i18next`.
- **Offline-resilient.** Riders lose signal in the city's older neighborhoods; orders cannot be lost when the radio drops.
- **Trust signals over feature breadth.** First-time users need to see verified riders, clear pricing, and a real phone number before they will tap *Order*.
- **Sovereign map stack.** No SDK pricing surprises, no third-party takedowns — the same MapLibre + OSRM + TileServer GL pipeline serves web, mobile, and the admin's rider map.

## How it's built

**Mobile.** The customer and rider apps run on **Expo SDK 56** with the **New Architecture** turned on, **continuous native generation** so we never commit `ios/` and `android/`, and **EAS Build + Updates** as the release pipeline. Server state is **TanStack React Query** with **persist + sync storage** so the apps cold-start instantly with the last known shape of orders, riders, and pricing. Local persistence uses **react-native-mmkv** (sync, fast) instead of AsyncStorage. Maps render through **`@maplibre/maplibre-react-native`** on both customer and rider sides. Push and in-app notifications run through **Notifee** + **React Native Firebase Messaging**. Animations are **Reanimated 4**. Forms use **React Hook Form**. Icons come through **`lucide-react-native`**.

**Backend + admin.** The API tier and operator panel are one **Laravel 13** codebase (PHP 8.4). The admin lives at `/admin` on **Filament 5**, roles through **spatie/laravel-permission**. Data on **PostgreSQL 16 + PostGIS**; sessions, cache, and queues on **Redis 7**; queue monitoring through **Horizon** at `/horizon` (super-admin only). Real-time channels for the rider map + live delivery events run on **Laravel Reverb**. Authentication is split by client: **Sanctum + SMS OTP** for mobile and web, **session + TOTP** for the admin. Money is stored and rendered as **integer ETB cents** across every surface — no float rounding ever reaches the ledger.

**Web.** The marketing site + Telegram Mini App run on **Next.js 16.2** with **React 19**, **Tailwind v4**, **GSAP** for the timeline-heavy scroll moments and **Framer Motion** for component-scoped transitions. Type-safe API contracts are generated from `docs/openapi.yaml` via **`openapi-typescript`** — the site can never call an endpoint that doesn't exist.

**Design system.** A shared `@fida/ui` package owns the design tokens, the typography scale, and a primitive set — Button, Sheet, Field, Badge, Pill, MapView, AddressCard — that both mobile apps consume identically. Color, radius, and motion are bound to tokens so a single change in the theme file updates both apps, the marketing site, and (with a small bridge) the Filament theme.

A `MockServer` adapter sits between the apps and the live API. Default-on mock data means every screen renders without the backend — designers can iterate without waiting on infra, and QA can reproduce any state by toggling a fixture.

## What I learned

Vertical integration — same designer, same engineer across two mobile apps, a marketing site, a Telegram Mini App, and a Filament admin panel — let the brand cohere in a way a typical contractor handoff never produces. A pill in the customer app feels exactly like a pill in the rider app because it *is* the same pill; the operator dashboard uses the same red, the same radius, the same typographic scale. The cost is that the bus factor is one. The next phase is hiring a second engineer onto the shared component package so the system survives me.
